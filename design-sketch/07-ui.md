# Operator UI

## One frontend, two shells

The web UI is one build. `agentd` serves it (embedded static assets) and exposes a multiplexed WebSocket. The Tauri app loads the same UI and connects to the same local WebSocket with a per-launch token. Tauri only adds native extras: starting or finding the daemon, tray icon, notifications, a global shortcut, and window management. There's one transport and one set of client code, so "works in Tauri, broken remotely" bugs mostly can't happen.

Stack, as specified by the operator: TypeScript, React, Radix UI, React Router, Vite, Vitest, Playwright. Terminal rendering is xterm.js with its addons.

## Features

### Groups

- List groups with state, branch, backend, member count, and activity.
- Create a group: pick a repository and a branch (existing or new), a backend, an initial set of agents, and policy (egress allowlist, remote access).
- Pause, resume, broadcast, snapshot, and tear down, with confirmation for anything destructive and a warning for unpushed commits.

### Sessions

- For each group, show agents and shells with live status (working, idle, blocked, exited) from hooks.
- Spawn an agent (harness, name, role, initial brief) or a shell (bash, fish, or zsh; named or scratch).
- Attach to any session in an xterm.js pane: tabs, splits, or a grid of several. Detach, restart, resume with the harness's native resume, or remove.
- Blocked sessions (for example a pending permission prompt) are surfaced prominently, since that's what needs the operator most often.

### Files

- Browse the group's worktree as a tree, with git status per file.
- View files with syntax highlighting, and diffs against the base branch or `HEAD`.
- Live updates when files change (file watching on the host side of the mount).
- Read-only for the PoC. Editing can come later.
- The daemon's file API is scoped to the group's worktree, resolves symlinks before checking the path, rejects traversal, caps sizes, and detects binaries.

### Messages

- A timeline per group of every bus message, with filters by agent, channel, and kind.
- Threads grouped by correlation ID, with delivery and acknowledgment state per recipient.
- A composer that sends as the operator to one agent, several, or the whole group.
- All peer-supplied text is sanitized before rendering.

### Shared context

- Browse checked-in and worktree-local memory, decisions, and claims.
- Promote worktree-local entries to checked-in memory at teardown, with review.

### Settings

- Backends and images, egress allowlists, remote access (Tailscale) status, whether remote shells are enabled, and default shell.

## Mobile

A phone keyboard makes a full terminal hard to use. The remote default on small screens should be a status view: sessions and their states, pending permission prompts with approve and deny where the harness supports it, and a box that sends a bus message to an agent or the group. The full terminal stays available.

## Frontend structure (suggestion)

- A protocol package with types generated from the daemon's schema.
- A client package: one WebSocket connection, request and response correlation, subscription management, reconnect with snapshot restore, flow control.
- A UI package of Radix-based components.
- The app: React Router routes such as `/groups`, `/groups/:group`, `/groups/:group/sessions/:session`, `/groups/:group/files/*`, `/groups/:group/messages`, `/settings`.
- Tests: Vitest for units and components; Playwright against a real daemon with a fake backend for most flows, and against the Apple Containers backend for the end-to-end demo.
