# Shell scripting research gate: raw notes

Recorded 2026-09-26 for issue #30. `[documented]` cites versioned source at the commits in `versions.md`. `[verified]` means a targeted local command confirmed the stated behavior at the versions in that file. `[observed]` is a narrower run outcome. `[inference]` is a proposed project rule drawn from the evidence. `[untested]` names an open runtime question. Probe commands and representative output are kept below so later workers can repeat them. Source paths below are relative to the clone roots in `versions.md`.

## Scope and interpreters

- [observed] All eight current `scripts/*.sh` files start with `#!/usr/bin/env sh`. They run as `/bin/sh` or whichever `sh` PATH selects when directly executed. The new ShellCheck and shfmt gate targets these eight files. `research/imported/verify.sh` is verbatim imported material outside this gate, per the import rule.
- [documented] Claude Code 2.1.283 command hooks accept a `shell` value of `bash` or `powershell`, while `args` uses exec form with no shell. See `experiments/00-system-assessment/harness-research.md:101` and its vendor hooks source. [inference] A hook that needs a specific interpreter should call an executable script with an explicit shebang or an explicit interpreter rather than assume the user's login shell.
- [documented] Codex CLI 0.157.1 builds command hooks with `$SHELL -lc <command>`, with the hook's working directory and piped standard streams. See `experiments/00-system-assessment/harness-research.md:363` and the pinned Codex source cited there. [observed] This host sets `$SHELL` to `/bin/zsh`, so inline Codex hook commands are subject to zsh parsing here. A later Codex source change uses native POSIX spawning but retains the shell command form, per the assessment's version limit.
- [documented] agy 1.2.11 command hooks use `sh -c` on Unix, with the directory containing `hooks.json` as their working directory. See `experiments/00-system-assessment/harness-research.md:615-621`. [inference] A fish login shell does not make agy's inline hook command fish syntax.
- [untested] No agent image or project hook exists yet, so the interpreter of a future image entrypoint or a future changed harness release must be checked when it lands.

## Bash 3.2 versus Bash 5.3

- [verified] `/bin/bash --version` is 3.2.57 and the locally compiled release source prints 5.3.0. `a=(); set -u; printf '%s\n' "${a[@]}"` exits 127 with `a[@]: unbound variable` on 3.2, while 5.3 succeeds with zero array words. Both reject `${a[0]}` when element zero is unset. The precise zero-word expansion can be confirmed with `set -- "${a[@]}"; echo "$#"`. Bash `CHANGES:2990-2996` records the newer empty-array behavior. [inference] For a script that must run on both versions, avoid relying on an empty array expansion under `set -u`, or guard it explicitly. For `sh`, use positional parameters and a `while IFS= read -r` loop.
- [verified] `set -e; declare -A a; a[key]=value` fails at `declare -A` on 3.2 and succeeds on 5.3. Bash `CHANGES:6191-6208` introduces associative arrays in the later release, and `doc/bashref.texi:8606-8655` defines indexed and associative arrays. [inference] Avoid associative arrays in host-compatible Bash and POSIX scripts. A simple `case` or a different language is clearer for the small mapping needs expected in hooks.
- [verified] `mapfile -t a < <(printf 'a\nb\n')` fails with `mapfile: command not found` on 3.2 and yields two array elements on 5.3. `CHANGES:6141-6144` records its addition. [inference] Use `while IFS= read -r line || [ -n "$line" ]; do ...; done < file` for cross-version input, while remembering that piping into the loop changes its process context.
- [verified] `${x,,}` with `x=AbC` is a bad substitution on 3.2 and expands to `abc` on 5.3. `CHANGES:6191-6195` records case-modifying expansions. [inference] Use a `case` match for fixed tokens or `tr '[:upper:]' '[:lower:]'` when host compatibility is required, with locale behavior considered.
- [verified] `sleep .1 & wait -n` reports an invalid option on 3.2 and returns status zero on 5.3. `CHANGES:4745-4747` records `wait -n` as a later addition. [inference] Track explicit child PIDs and `wait "$pid"` when Bash 3.2 must run it.
- [verified] `coproc cat` reports `coproc: command not found` on 3.2 and sets `COPROC_PID` on 5.3. `CHANGES:6205-6208` and `doc/bashref.texi:1444-1516` define the coprocess syntax. [inference] Reserve it for a Bash 5-only image script if needed. It adds file descriptor and child lifecycle complexity to a hook.
- [verified] `local -n ref=x` inside a function is invalid on 3.2 and updates `x` through the reference on 5.3. `CHANGES:4725-4728` and `doc/bashref.texi:1826-1855` describe namerefs. [inference] Pass values through arguments and stdout in host-compatible scripts instead of using namerefs.
- [verified] `printf '%(%Y)T\n' -1` rejects the format on 3.2 and prints the current year on 5.3. `CHANGES:5142-5144` documents the format. [inference] Use `date` with a portable format for host-compatible scripts, and do not depend on GNU `date -d`.
- [verified] `shopt -s globstar` and `shopt -s lastpipe` both report invalid shell option names on 3.2. Both succeed on 5.3. `CHANGES:6148-6151` and `CHANGES:5161-5163` record their introduction. On 5.3 with job control off, `printf 'after\n' | read x` leaves `x=before` by default and changes it to `after` under `lastpipe`. `doc/bashref.texi:769-846` defines the pipeline process rule. [inference] Use `find` or explicit directory traversal when a Bash 3.2 script needs recursion, and redirect a loop's input rather than depend on `lastpipe`.
- [verified] `cat <(printf 'yes\n')` works on both Bash versions. `doc/bashref.texi:2954-2990` defines process substitution. [inference] It is a Bash feature, not a POSIX `sh` construct. An executable `#!/usr/bin/env sh` file must not use it even though host `/bin/sh` may happen to be Bash-derived.
- [verified] On both versions, `set -e; f(){ false; echo continued; }; if f; then echo true; fi; echo after` prints `continued`, `true`, and `after`. `set -e` is ignored in the conditional call context, including commands in the function. Bash `doc/bashref.texi` section `The Set Builtin` explains the exceptions. [inference] Check expected failures with explicit `if command; then ... else ... fi` and avoid treating `set -e` as complete error handling.
- [verified] On both versions, `false | true` has status zero by default and status one after `set -o pipefail`. Bash `doc/bashref.texi:830-846` defines the rightmost nonzero pipeline status. [inference] Use `pipefail` only under an explicit Bash or zsh interpreter, and separately inspect where a pipeline runs before relying on variable assignments or `set -e`.

## zsh and fish for hooks

- [verified] `/bin/zsh -lc 'x="two words"; printf "<%s>\n" $x'` prints one `<two words>` argument. Bash splits that unquoted scalar into two words. zsh `Doc/Zsh/expn.yo:585-637` and `Doc/Zsh/options.yo:2387-2405` define `SH_WORD_SPLIT`, which changes the behavior. [inference] Quote data and pass paths as distinct arguments. Avoid carrying Bash snippets into Codex's `$SHELL -lc` hook string.
- [verified] `/bin/zsh -lc 'printf "%s\n" /tmp/issue30-none-*.zzz; echo survived'` exits one before the echo with `no matches found`. `Doc/Zsh/options.yo:711-730` describes `NOMATCH` and `NONOMATCH`. [inference] Test a path before globbing or use zsh's explicit null-glob qualifier in zsh-only code. A portable script can use `for f in pattern; do [ -e "$f" ] || continue; ...; done`.
- [verified] `a=(one two); echo "${a[1]}"` returns `one` in zsh and `two` in Bash. `setopt ksharrays` makes zsh's element one `two`. `Doc/Zsh/options.yo:2089-2112` records the switch. [inference] Do not share array-indexing snippets across shells.
- [documented] zsh uses `setopt` and `unsetopt` for options including `NOMATCH`, `SH_WORD_SPLIT`, `GLOB_SUBST`, and `KSH_ARRAYS`. `Doc/Zsh/options.yo` defines them. [observed] The local `zsh -lc` probe behaved with `NOMATCH` on and word splitting off. [inference] Setting compatibility options in a caller's shell is fragile, so write a script for its selected interpreter.
- [documented] fish 4.0.8 is intentionally not POSIX compatible. It uses `set` for variables, `$argv` for arguments, `$status` for exit status, and splits command substitution output on newlines. Unmatched globs normally fail the command. `doc_src/fish_for_bash_users.rst:6-34`, `:102-120`, `:176-185`, and `doc_src/cmds/set.rst:24-55` document these facts. [untested] Fish is absent here, so none was runtime-verified. [inference] A fish user can run a hook's executable POSIX or Bash script by path, but inline `sh -c`, `bash`, and `zsh -lc` hooks need their own syntax regardless of the user's interactive shell.

## GNU and BSD userland

- [observed] PATH selects GNU `sed` 4.10, coreutils 9.11, findutils 4.11.0, and gawk 5.4.1 on this macOS host. `/usr/bin/sed`, `/bin/date`, `/usr/bin/stat`, `/usr/bin/head`, and `/usr/bin/find` expose Apple command variants. These host versions and paths are in `versions.md`. `scripts/*.sh` currently call `basename`, `grep`, `sed`, `awk`, `tr`, and `xargs`, with `xargs -r` in the Markdown and Mermaid checks.
- [verified] GNU `date -d tomorrow` works, while `/bin/date -d tomorrow` rejects `-d` and accepts `-v+1d`. GNU `stat -c '%s' AGENTS.md` works, while `/usr/bin/stat -c` rejects `-c` and accepts `-f '%z'`. GNU `head -n -1` and `find -printf` work, while the Apple commands reject them. GNU `sed -i` has no required backup argument, while Apple sed documents `-i extension`. [inference] Scripts expected to run in Linux CI, the agent image, and a stock Mac must avoid those dialect-specific flags or branch deliberately by tool implementation. The developer's GNU-first PATH applies only to this host.
- [documented] GNU coreutils `doc/coreutils.texi:12486-12528` documents `stat --format` and `:16366-16385` documents `date -d`. The Apple command source's `date/date.1:446-494` documents `-v`, and `sed/sed.1:629` demonstrates `sed -i ''`. The installed-command probes above determine behavior on this host because the Apple source snapshots in `versions.md` are not proven to match this macOS build.

[inference] `xargs -r` is available on this tested macOS build and GNU findutils, but POSIX does not require it, so a future broader target should replace it with explicit input checking. Filename lists piped to `xargs` are newline-delimited and would fail for a Markdown path containing a newline. That edge is outside this linter gate and should be handled in the calling workflow if such paths are admitted.

## ShellCheck and shfmt proposal

- [documented] ShellCheck 0.11.0 detects quoting, array and subshell mistakes, suspicious constructs, and portability relative to the script's shebang. It supports sh, Bash, dash, and ksh, not zsh or fish. `README.md:435-500`, `:564`, `shellcheck.1.md:9-36` and its SC1071 rule. [documented] shfmt 3.14.0 parses and formats POSIX shell, Bash, zsh, and mksh, with automatic dialect detection from extensions or shebangs and `-d` for a formatting diff. `README.md:5-24`, `cmd/shfmt/shfmt.1.scd:23-78`. It is a formatter, not a behavioral proof.
- [inference] Pin ShellCheck 0.11.0 and shfmt 3.14.0 in `mise.toml`. For current `scripts/*.sh`, run `shellcheck --severity=style` and `shfmt -d -i 4 -ci`. Add `fmt:shell` and `check:shell`, include the latter in `check`, and run both through mise-backed prek hooks. Four-space indentation matches the present scripts. No global ShellCheck suppression or shell override is needed.
- [verified] `mise exec -- shellcheck --severity=style scripts/*.sh` reported no findings before formatting. `mise exec -- shfmt -d -i 4 -ci scripts/*.sh` identified only `scripts/check-experiments.sh`, `scripts/check-gofumpt.sh`, and `scripts/check-pr-body.sh`. `mise run fmt:shell` changed only their case/brace layout and case-pattern spacing. `mise run check:shell` then passed. The other five scripts require no change or exemption.
- [inference] The gate currently selects repository-owned `scripts/*.sh`. When hook or agent-image shell files arrive, extend the task and prek file matcher in the same PR so they are included. Do not lint `research/imported/verify.sh`, which is immutable imported evidence.
- [inference] Neither tool can prove runtime interpreter selection, environment, external command availability, GNU/BSD flag compatibility, races, permissions, hook JSON protocol behavior, or process cleanup. ShellCheck has no zsh or fish semantic analysis and cannot model every shell option or dynamic `eval` path. Verify those with targeted process tests on the actual host and image versions when the hooks are implemented.
