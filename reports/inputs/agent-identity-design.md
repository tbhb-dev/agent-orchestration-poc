The operator-only sensitive merge action uses `tbhbagent` transport with a `merge-sensitive` record bound to current PR head, current main, policy version, and exact title/body. Approval of this design is not approval of a future merge. The #135 agent can propose its own policy change but cannot authorize or merge it.

The proposed macOS deployment uses service principal `_agent_signer`, client group `_agent_sign_clients`, socket `/var/run/agent-commit-sign.sock` owned by that principal/group with mode `0660`, and root-owned adapter `/usr/local/libexec/agent-commit-sign` with mode `0755`. Add only the worker OS account to the client group. Keep private state and the authorization store under `/Library/Application Support/agent-orchestration-poc/signer/`, owned by `_agent_signer` with directory mode `0700` and private-file mode `0600`. Install the service definition as root-owned `/Library/LaunchDaemons/net.tonyburns.agent-commit-sign.plist`, mode `0644`, running as `_agent_signer`. These are proposed host changes that the operator must approve and execute.

Place public policy and verification material under `/Library/Application Support/agent-orchestration-poc/verification/`, root-owned with directory mode `0755` and file mode `0644`. Workers receive read access only. The operator's separate control session authorizes requests through a service-admin operation unavailable to the client group. A worker can connect to the socket but cannot create authorization records. Grant each harness access to that exact socket and read-only adapter/policy paths, without adding the private state directory to readable or writable roots. Harness-specific settings and OS access behavior remain untested and must be recorded before #134. If a harness cannot express this grant, stop and revise the plan instead of widening access.

The signer, independent authorization store, account adapters, and full detector require code and verification before cutover. Fingerprint values require operator confirmation because this worker cannot inspect key material. For #134, the operator's authorization must identify the service artifact digest and final harness settings alongside the public fingerprint values. The paths above are proposals, not a blanket host grant or an assertion that the service exists.

## Failure and rollback

Before activation, failure leaves dispatch stopped or restores the unchanged old policy after operator review of any completed account changes. Do not resume old workers merely because login succeeded. After activation, retain `tbhbagent` as default, stop signing and mutations on identity or detection failure, and preserve redacted receipts. Roll back through a reviewed operator-merged PR under the active rules. Removing `required_signatures` from ruleset 24053242 needs a separate exact operator authorization and readback, with all other protections preserved. Neither credential access nor a failed check authorizes bypass.

On accidental `tbhb` use, the prepared response is to revoke the exposed operator credential, remove its host copies as the operator, invalidate affected authorizations, reissue only in a separate operator OS account/host, and retain a restricted configuration broker if needed. Report all post-cutover `tbhb` communication, including legitimate human comments, and reconcile each against the independent channel. Unexplained events or missing coverage keep workers paused. Do not describe this future response as current isolation.

## Functional boundaries and verification ownership

Future pure functions parse roles and endpoints alongside payloads, authorizations, signature results, commit populations, and cutover time. It decides allowed/refused actions from plain values. The shell alone calls GitHub, Git, the signer, storage, clocks, or processes. Every core function needs table and property tests with no mocks. Shell process and endpoint tests bind loopback only. This PR contains documentation.
