## What went well

Phase 0 reached an approved plan in about 3 hours 17 minutes, from the scaffold commit to the merge of PR #2. The assessment, decisions brief, and checkpoint report landed in [PR #1](https://github.com/tbhb/agent-orchestration-poc/pull/1); [PR #2](https://github.com/tbhb/agent-orchestration-poc/pull/2) recorded the approval in `HANDOFF.md`.

`experiments/00-system-assessment/` records the system assessment, dependency revisions, model calls, and limits of the evidence. The assessment installed or started nothing; `experiments/00-system-assessment/dependency-clones.md` records 23 source clones with commits and nearest tags.

The decisions brief in `reports/inputs/phase-0-decisions.md` was committed before the coordinator session changed. Both merged PRs used squash commits, and their bodies carried the PR bodies as configured.

## What cost time

A research subagent finished its sub-reports but did not assemble or report them; the coordinator waited nearly two hours. The cause, whether the dispatch brief or the harness, was not established. `reports/inputs/phase-0-retro-findings.md` records the stall, and `PLAN.md`, Retrospectives, devlog, and mechanical checks, now requires a scheduled check-in for dispatches longer than fifteen minutes.

The first `codex exec` document run could not commit from a linked worktree until the repository's common `.git` directory was added to its writable paths. `reports/phase-0-checkpoint.md` records the failure, and `HANDOFF.md` records the `--add-dir <repo>/.git` launch requirement.

The plan needed one revision after the initial draft, including model assignments, retrospectives, devlog, and session rollover. Mise shims were absent from non-interactive shells, so `mise install` was deferred to phase 1 tooling; see `experiments/00-system-assessment/evidence.md`.

## What broke

The common `.git/info/exclude` contained `/INPUTS/`, which hid `reports/inputs/` on the case-insensitive filesystem. The entry remained in place when the findings were gathered, so the collision can recur.

`HANDOFF.md` still described PR #2 as open after it merged. Both phase 0 PRs merged with no CI, recorded review, or comment; the coordinator's review therefore left no GitHub record. The first three history commits carried `Assisted-by:` trailers, contrary to the later commit convention, although the squash commits on `main` were clean.

There was no bus log, CI output, or worker roster for this period. Phase 0 used one-shot coordinator subagents; there were also no reported worker hook denials or sandbox failures and no Project items in Blocked.

## Decisions

- `agentd` begins as the provisioner and grows into the daemon, with `agentctl` as its CLI; `PLAN.md`, Names.
- One root Go module, a shared Python helper package, pnpm workspaces, numbered experiments, and isolated worktrees define the repository shape; `PLAN.md`, Repository layout.
- Conventional commits with `Refs:`, squash merges, coordinator review, and mise-based CI define the GitHub workflow; `PLAN.md`, GitHub workflow.
- Nine interactive workers, three per harness, use explicit models and effort levels, while `agy` receives bounded tasks; `PLAN.md`, The build group, Concurrency, and Models and effort levels.
- Per-harness unattended permission modes retain the intended sandbox boundaries, subject to runtime verification; `PLAN.md`, Permission modes.
- Checkpoint retrospectives and daily or checkpoint devlog entries preserve decisions and propose mechanical checks; `PLAN.md`, Retrospectives, devlog, and mechanical checks.
- Durable decisions, memory, and a regenerated `HANDOFF.md` support session rollover; `PLAN.md`, Coordinator session rollover.
- Research gates precede first code in each language and stack; `PLAN.md`, Research gates for languages and stacks.
