# Interactive turn state

## Scope and clock

This spike tests status observations for interactive workers before the completion reporter is built. The first disposable probe began at 2026-09-27T18:12:18Z, so the six-hour ceiling was 2026-09-28T00:12:18Z. Probes stopped before that ceiling after the stated two-attempt limits and setup boundaries. Each invocation was bounded to at most 120 seconds, below the issue's ten-minute per-probe limit. No session named `0`, `codex-app-server`, `cloudflared-gh`, or `webhook-capture-org` was touched. The only tmux sessions created and removed were `exp214-claude`, `exp214-claude2`, `exp214-agy`, and `exp214-agy2`.

The allowed read-only observations were `tmux capture-pane`, `tmux list-panes`, `tmux has-session`, `claude agents --json`, and Codex requests to an experiment-owned stdio app server. Claude's Stop hook was supplied as an invocation-local `--settings` JSON value that points to [stop-hook.sh](stop-hook.sh), with output in `/private/tmp/exp214-claude/`. No user settings file, host configuration, shared runtime, or credential was changed. An approval prompt was captured and never answered.

## Report-file fallback and negative cases

`EXP214_CAPTURE_DIR=/private/tmp/exp214-claude mise exec -- timeout 120 claude -p --restricted --tools '' --settings <invocation-local Stop JSON> 'Reply with EXP214-DONE.'` exited 0 in about three seconds with `EXP214-DONE`. It also produced one [Stop hook line](evidence/claude-hook.jsonl). This was print mode and proves hook delivery for that mode only. A later restricted print-mode request to write a report returned a denial without creating a file. A retry with `--permission-mode acceptEdits --setting-sources '' --tools Write` exited 0, replied `EXP214-REPORTED`, and wrote [claude-report.json](evidence/claude-report.json) in about 30 seconds. It did not establish automatic writing from an interactive session.

`mise exec -- timeout 120 agy --mode accept-edits --print='Write exactly {"schema":1,"worker":"agy","state":"finished","generation":"exp214-agy-1"} to /private/tmp/exp214-agy/report.json and reply EXP214-REPORTED.'` exited 0, replied `EXP214-REPORTED`, and wrote [agy-report.json](evidence/agy-report.json) in about nine seconds. The first syntax attempt placed `--mode` after bare `--print` and exited 2 before a turn. The corrected run logged sandbox denials for its home log and conversation paths, plus a missing-login diagnostic in [redacted stderr](evidence/agy-report-error-redacted.txt). Interactive status and persistence remain untested. A Codex worker-written report remained **inaccessible** after its owned runtime failed to initialize. No report was fabricated as Codex output.

`PYTHONSAFEPATH=1 NO_COLOR=1 PYTHONUNBUFFERED=1 mise exec -- python experiments/01-interactive-turn-state/report-probe.py` exited 0 in about 0.04 seconds. Its [JSONL capture](evidence/report-file.jsonl) separates the three file properties. A `gen-1` report from 2020 is stale when the expected generation is `gen-2` at the current run time. Before `Path.replace`, a reader sees the complete old final file while the new temporary file is incomplete. After replacement, the reader sees the complete `gen-2` report. Killing the writer with signal 9 left a partial temporary file and preserved the complete final file. This local filesystem test establishes atomic visibility under the recorded conditions. The report writer must place the temporary file in the same directory and atomically replace the final path. Power-loss durability also requires syncing the file and directory. The probe tested atomic visibility and process death, not power-loss durability.

A stored Codex thread is not proof of a loaded worker. The prior [Codex lifecycle research](../../research/imported/agent-session-tests/CODEX_SESSION_MANAGEMENT.md) observed `thread/read` returning `notLoaded` after server restart, while a later resume restored the same stored ID. The current owned-runtime test could not repeat that observation under this sandbox. A live tmux pane is also insufficient. The same Claude pane PID 91071 existed during a running command, after the completed reply, and at an approval wait, and the process-start query was denied. The detection rule rejects each of these inputs as insufficient evidence of idle.

## Input contract and detection rule

The later `tooling(workers): report worker completion without process exit` item should accept a minimal observation record with `run_id`, `harness`, `worktree`, `native_session_id`, `endpoint` when applicable, `process_pid`, `process_start`, `pane_id`, `turn_id`, `observed_at`, `source`, `turn_state`, and an optional worker-declared `task_complete`. A source may leave fields unknown. An empty field must not be promoted to a match. `turn_state` should be one of `active`, `finished_idle`, `waiting_approval`, `waiting_input`, `dead`, or `unknown`, with the raw native state retained beside the derived state. Keep task completion separate from turn completion.

Use a pure decision function over captured values. It returns `unknown` if the observation is stale, inaccessible, mismatched to the run or process generation, or conflicts with another fresh source. It returns a wait only from a correlated native wait signal. It returns `finished_idle` only after a matching turn-completion event or fresh worker report, plus a live idle observation for the same generation. It returns `dead` only after a correlated process or owned runtime loss, never from `notLoaded` or a missing pane alone. Otherwise return `active` when a fresh owned runtime reports work in progress, or `unknown`. The shell collects endpoint, hook, file, process, and tmux facts and performs the atomic report write. The core makes every classification and freshness decision without I/O.

The later reporter should test a Codex owned endpoint outside this sandbox with `thread/start`, `turn/start`, `thread/read`, loaded-list, both wait flags, and an experiment-owned runtime termination. It should compare an interactive Claude Stop hook with its registry wait status while preserving PID and process start. It should obtain an operator-provided exact-worktree agy trust decision or a supported no-settings-write launch path before repeating agy's interactive cells. The current evidence supports `unknown` for Codex and agy interactive completion here and for Claude states that require a registry or process-generation match.

Issue #153 consumes status observations for stopped-run triage and must keep a live idle session distinct from an ended run. Issue #176 and PR #192, #196, #211, and #213 concern launch and readiness. PR #216's trust registration is a separate #176 delivery and is ineligible for this no-settings-write spike. This experiment changes none of those implementations.

## Boundaries and cleanup

The exact blocked Codex action was initializing the SQLite state runtime under `/Users/tony/.codex` for an experiment-owned `codex app-server --stdio`. Continuing would require operator-approved write access for that state path or an operator-prepared isolated runtime with usable authentication. No alternative home, credential copy, or shared endpoint was used. The exact agy blocked action was selecting `Yes, I trust this folder` for `/private/tmp/exp214-agy` or this worktree. That consent may persist in harness user settings, so no choice was made. Claude's first temporary-folder trust prompt was handled the same way. The operator can review these precise blocked actions. I stopped both probes before changing settings or host access.

Sessions `exp214-claude`, `exp214-claude2`, `exp214-agy`, and `exp214-agy2` were removed. The Claude permission request was left unanswered and its marker file was absent after cleanup. The app-server child exited 1 and was reaped by the probe. The report-probe child was killed and reaped within its temporary directory, which was removed. `agy remote-control status` said `not running`, and no daemon was started. Temporary report files and the redacted raw agy stderr remain under `/private/tmp/exp214-*` for local audit. No shared session or runtime was stopped.
