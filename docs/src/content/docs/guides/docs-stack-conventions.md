## Project shape

Configure Astro 7.3.5 in `docs/astro.config.mjs` with `// @ts-check`, `defineConfig`, and `starlight({ title, sidebar, plugins })` in `integrations`. `title` is Starlight 0.42.4's only required option (withastro/starlight@3ec633b `examples/basics/astro.config.mjs`, `docs/src/content/docs/manual-setup.mdx`, research/gates/docs-stack/notes.md §1).

Define the `docs` collection in `docs/src/content.config.ts` using `docsLoader()` and `docsSchema()`. The loader reads Markdown, MDX, and Markdoc below `docs/src/content/docs/` and ignores names beginning with `_` (withastro/starlight@3ec633b `examples/basics/src/content.config.ts`, `docs/src/content/docs/reference/configuration.mdx`, research/gates/docs-stack/notes.md §1).

Starlight 0.42.4 requires `title` frontmatter. Use `description` for page summaries, `sidebar.label` and `sidebar.order` for autogenerated entries, and `draft: true` to exclude a page from production. Sidebar frontmatter does not apply to a `link` item, and a draft cannot be targeted by sidebar `slug` (withastro/starlight@3ec633b `docs/src/content/docs/reference/frontmatter.md`, research/gates/docs-stack/notes.md §1).

Use explicit, ordered top-level sidebar groups with `autogenerate` for directory contents. Add a page in its section directory without changing the config. Keep Devlog as a `link` item, and set Retros `sidebar.order` when alphabetical dated-file order is unsuitable (withastro/starlight@3ec633b `docs/src/content/docs/guides/sidebar.mdx`, HiDeoo/starlight-blog@19e7832 `docs/astro.config.ts`, research/gates/docs-stack/notes.md §1).

Avoid older config examples. Starlight 0.42.0 removed `tagline`. Astro 7 defaults to Sätteri and requires the explicit unified processor for remark/rehype plugins. In Astro 6, collections moved to `src/content.config.ts`, legacy collections were removed, and `z` imports moved to `astro/zod` with Zod 4 syntax (withastro/starlight@3ec633b `packages/starlight/CHANGELOG.md`, withastro/docs@99dba9d `src/content/docs/en/guides/upgrade-to/v6.mdx`, `upgrade-to/v7.mdx`, research/gates/docs-stack/notes.md §1).

## Diagrams

Render fenced `mermaid` blocks at build time with `rehype-mermaid` 3.0.0, `strategy: 'inline-svg'`, and `mermaidConfig: { theme: 'neutral' }` on `markdown: { processor: unified({ rehypePlugins: [[rehypeMermaid, { strategy: 'inline-svg', mermaidConfig: { theme: 'neutral' } }]] }) }` from `@astrojs/markdown-remark` 7.3.1 (remcohaszing/rehype-mermaid@cab7b87 `README.md`, withastro/docs@99dba9d `src/content/docs/en/guides/upgrade-to/v7.mdx`, research/gates/docs-stack/notes.md §2).

The resulting static SVG does not follow Starlight's theme toggle, and `astro build` fails on a rendering error when no `errorFallback` is set. `astro-mermaid` 2.1.0 is rejected because its Mermaid peer range excludes 12.0.0, an Astro 7 MDX rendering issue is open, and its browser rendering cannot validate diagrams at build time (remcohaszing/rehype-mermaid@cab7b87 `README.md`, withastro/starlight@3ec633b `packages/starlight/src/style/props.css`, `joesaby/astro-mermaid` issues 74 and 75, research/gates/docs-stack/notes.md §2).

Before committing a diagram, validate its fenced source with the repository-wide Mermaid CLI check and build the docs with Chromium installed. The build checks diagrams in `docs/`, while the CLI check covers fenced diagrams elsewhere in the repository (PLAN.md §Retrospectives, devlog, and mechanical checks, research/gates/docs-stack/notes.md §2).

## Devlog

Use `starlight-blog` 0.30.0 in Starlight's `plugins` with `title: 'Devlog'`, `prefix: 'devlog'`, and `navigation: 'none'`. Extend the collection with `docsSchema({ extend: (context) => blogSchema(context) })` from `starlight-blog/schema`, and add `{ label: 'Devlog', link: '/devlog/' }` to the sidebar (HiDeoo/starlight-blog@19e7832 `docs/src/content/docs/getting-started.mdx`, `configuration.md`, `docs/astro.config.ts`, research/gates/docs-stack/notes.md §3).

Write entries at `docs/src/content/docs/devlog/YYYY-MM-DD-<slug>.md` with `title`, YAML `date`, `tags`, and a configured `authors` id naming the harness and model. Extend the schema for the plan's `phase` frontmatter field. Cover landed PRs, decisions and evidence, experiments and results, resolved problems, and what comes next. Produce at least one entry for each working day with merges, experiment results, or decisions, and at checkpoints. The first entry covers phase 0. The dated-pages fallback is dropped for this compatible Starlight 0.42.4 and blog 0.30.0 pairing (HiDeoo/starlight-blog@19e7832 `docs/src/content/docs/guides/frontmatter.md`, `packages/starlight-blog/package.json`, PLAN.md §Devlog, research/gates/docs-stack/notes.md §3).

## Package management

Pin pnpm 12.7.0 in `mise.toml` and `"packageManager": "pnpm@12.7.0"` in the private root `package.json`. Keep the root `pnpm-workspace.yaml` package list to `docs`, put site dependencies in `docs/package.json`, and commit `pnpm-lock.yaml`. The tooling PR pinned 12.7.0 before the notes recommended 12.6.0. The one-patch difference is resolved in favor of the existing pin (pnpm/pnpm.io@e7dc3d4 `docs/workspaces.md`, `docs/package_json.md`, research/gates/docs-stack/versions.md, research/gates/docs-stack/notes.md §4).

CI installs with `pnpm install --frozen-lockfile`, which rejects a missing or stale lockfile. Review dependency build scripts by name in `allowBuilds` in `pnpm-workspace.yaml`, with `esbuild: false` and `sharp: false` as the documented starting entries, and do not use `dangerouslyAllowAllBuilds` (pnpm/pnpm.io@e7dc3d4 `docs/cli/install.md`, `docs/settings/build.md`, withastro/starlight@3ec633b `pnpm-workspace.yaml`, research/gates/docs-stack/notes.md §4).

Biome 2.5.14 checks site `.mjs`, `.ts`, `.js`, and `.json` files. Force-ignore `docs/.astro`, `docs/dist`, and `**/node_modules` with `!!` patterns in `files.includes`. Biome checks only the JavaScript frontmatter of `.astro` files by default. Markdown and MDX use rumdl and Vale, while YAML uses ryl (biomejs/biome@088164f `packages/@biomejs/biome/configuration_schema.json`, `crates/biome_service/src/file_handlers/astro.rs`, research/gates/docs-stack/notes.md §4).

## Build, tasks, and CI

Run `mise run docs:dev` for `pnpm exec astro dev` and `mise run docs:build` for `pnpm exec astro build`, both from `docs/`. The default build output is `docs/dist/`, and Astro's generated cache and types are in `docs/.astro/`. Both directories are gitignored (withastro/docs@99dba9d `src/content/docs/en/reference/cli-reference.mdx`, `reference/configuration-reference.mdx`, withastro/starlight@3ec633b `examples/basics/.gitignore`, research/gates/docs-stack/notes.md §5).

Install the Playwright 1.63.0 Chromium browser before the CI build with `pnpm exec playwright install --with-deps chromium`, then build with `CHECK_LINKS=1` to enable `starlight-links-validator` 0.26.0. It fails the build on broken internal links and hashes. Its validation invalidates the content-layer cache, so local development keeps the flag unset (remcohaszing/rehype-mermaid@cab7b87 `README.md`, HiDeoo/starlight-links-validator@b725855 `docs/src/content/docs/getting-started.mdx`, `configuration.md`, research/gates/docs-stack/notes.md §§2, 5).

If `astro check` is adopted, pin TypeScript to 6.x, currently 6.0.3, because `@astrojs/check` 0.9.10 accepts TypeScript 5 or 6, not the latest 7.0.2 (research/gates/docs-stack/versions.md, research/gates/docs-stack/notes.md §5).

## Quality gates

Biome 2.5.14 checks TypeScript and JavaScript functions for cognitive complexity 15, length 60 lines, and at most 5 parameters. The rules are `noExcessiveCognitiveComplexity`, `noExcessiveLinesPerFunction`, and `useMaxParams` in the `complexity` group, each at error level in `biome.json`. Run `mise run check:biome`. jscpd 5.3.2 also checks duplicate TypeScript blocks at 50 tokens and 5 lines through `mise run check:dupl`. Recalibrate thresholds at the first retro with phase 2 code (research/gates/quality-gates/notes.md §Complexity).
