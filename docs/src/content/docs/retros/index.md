title: Retrospectives
description: Checkpoint and ten-PR reviews with mechanical follow-ups.
---

Run a retrospective at every phase checkpoint and after every ten merged PRs during a phase. A worker gathers evidence, and Codex writes the page. Cover what went well, what cost time, what broke, decisions, and action items.

Each retrospective proposes at least one mechanical check or explains why none applies. File action items as `type/tooling` or `type/process` issues in the Project. Inputs include review turnaround, CI failures, worker stalls, sandbox denials, and coordinator interventions. Bus logs become an input once the bus exists.
