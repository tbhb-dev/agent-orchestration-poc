## What cost time

Creation-to-merge time across the 15 phase 1 PRs ranged from 1 minute 13 seconds to 11 minutes 28 seconds, with a median of 4 minutes 24 seconds. The timestamps measure elapsed PR time. All 15 have empty GitHub review arrays, so time to first submitted review is unknown. Shell review activity is outside that record. `merged-prs-refresh.json.txt` and `reviews.json.txt` preserve the measurements.

The tooling branch needed a rebase after two merges and a Vale exemption pass. Codex pages needed another prose pass for semicolons in citation lists. zsh word splitting broke two coordinator scripts. The coordinator inputs estimate a four-and-a-half-hour session, while the PR timestamps cover only the merge window. They do not establish total active work time.

## What broke

The initial 40-run snapshot contains 37 successes and three cancellations. The expanded 62-run snapshot contains 56 successes, three cancellations, two unfinished runs, and one failure. [Run 36273718796](https://github.com/tbhb/agent-orchestration-poc/actions/runs/36273718796) failed when rumdl rejected `HANDOFF.md:27` linking to `../../.git/info/exclude`. That path existed only in the local checkout layout. `ci-failure.txt` preserves the failed log, and the next CI revision passed. Cancellations are separate from failures.

Ruff initially reached the imported research and fenced Markdown code. Exclusions corrected that scope. The docs PR predated CI and acquired checks after rebasing. `gh pr checks --watch` returned before `check` finished, and issue #6 was closed early and reopened. The saved issue events establish the closure and reopening. The command behavior comes from the coordinator inputs.

Claude auto mode denied a merge, a settings edit, and a cleanup. The operator changed local permissions. Codex could not run Chromium inside its sandbox, so docs rendering and link validation ran in CI. The coordinator's Bash tool limits commands to ten minutes, so longer Codex runs were detached. These observations cover this session only.

The bus is still unbuilt, so message latency, unanswered bus questions, and worker last-seen measurements are unavailable. The saved issue list is a state snapshot and cannot establish every historical Project transition to Blocked.

## Decisions

- Keep functional core, imperative shell binding, with boundary checks for every language. [#58](https://github.com/tbhb/agent-orchestration-poc/issues/58) and [PR #66](https://github.com/tbhb/agent-orchestration-poc/pull/66) record depguard, import-linter, Ruff TID251, and the core and shell paths.
- Require property tests, mutation tests, duplicate-code checks, dead-code checks, and complexity limits. [PR #67](https://github.com/tbhb/agent-orchestration-poc/pull/67) and [PR #68](https://github.com/tbhb/agent-orchestration-poc/pull/68) supply research. Those checks must run before phase 2 core code can merge.
- Use strict pyrefly, with two annotation relaxations in tests and experiments pending an operator decision. [PR #65](https://github.com/tbhb/agent-orchestration-poc/pull/65) and [decision 0002](/decisions/0002-python-type-checker/) record the change.
- Shift coding and research to Sol at high, and reviews and design documents to Astra at medium. Keep Fable for coordination and Sonnet 5 for bus, credentials, and security cross-checks. The [checkpoint](/project/phase-1-checkpoint/) records usage and the confirmation request.
- Keep raw research notes exempt under `research/gates/`, lint pages written from them, and keep root plan and handoff files as pointers. The plan retains its existing exemption.
