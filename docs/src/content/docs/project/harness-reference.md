## Unattended launch boundaries

Workers run unattended inside their assigned sandbox. The coordinator reports blocks to the operator and never types approvals into worker terminals. Claude Code's approved launch uses `--permission-mode auto` with an operator-controlled settings file, sandboxing, and local binding. Its `acceptEdits` fallback was proposed but not established as prompt-free. Codex uses workspace-write with approval policy `never` and a per-launch network override. The recorded override opens all outbound network, so the narrower local-binding candidate remains an untested phase 2 experiment. Codex needs the repository's common `.git` directory writable to commit from a worktree. `agy` uses its sandbox and an approved unattended permission mode, with runtime boundary and loopback behavior still requiring the phase 2 test. See [plan, Permission modes](/project/plan/#permission-modes) and [worker policy](/project/worker-policy/#operator-and-credential-boundaries).

The recorded launch arguments are `claude --permission-mode auto --settings <per-worker settings file>`, `codex -s workspace-write -a never`, and `agy --sandbox --dangerously-skip-permissions --prompt-interactive "<pointer to brief>"`. Codex also needs `sandbox_workspace_write.network_access=true` per launch and the common `.git` path as an added writable root. Claude settings include sandbox enabled, sandboxed Bash auto-allow, and local binding at user scope. The `agy` `toolPermission: proceed-in-sandbox` variant was proposed for testing first. These strings are [documented and observed at the recorded versions](/project/plan/#permission-modes), with untested runtime boundaries called out there.

Persistent user settings and user-scope hooks need operator approval. Send permission requests through AskUserQuestion so the operator receives a mobile notification. Pass credentials by path, never by secret contents in an environment variable or argument. Codex's `shell_environment_policy.inherit = "core"` may drop injected worker variables, so the launch must explicitly provide needed non-secret values. These are [plan, Codex](/project/plan/#codex) requirements, not a runtime guarantee for newer versions.

## Model and effort assignments

Name model and effort on each launch and in the issue. The phase 1 revision assigns `gpt-6-sol` at high for coding and research, `gpt-6-sol` at medium for routine docs, `gpt-6-astra` at medium for reviews and design documents, and `claude-sonnet-5` at medium for cross-checks of bus semantics, credentials, and security. First-pass PR review uses `codex exec review`. `agy` waits for the provisioner. The coordinator can adjust per issue. The [plan, Assignments](/project/plan/#assignments) and [phase 1 inputs](https://github.com/tbhb/agent-orchestration-poc/blob/main/reports/inputs/phase-1-coordinator-notes.md) record this dated decision. Historical standing-roster defaults in [plan, The build group](/project/plan/#the-build-group) are superseded where they disagree.
