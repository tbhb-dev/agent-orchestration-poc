# Intake agent brief

## Authority and stage

This brief is contract version 1 for [issue #198](https://github.com/tbhb-dev/agent-orchestration-poc/issues/198). The dedicated intake agent alone writes Project drafts and converts them to repository issues. The coordinator launches it only after posting an activation comment on #198 with a UTC activation time and this policy version and location. The organization Project is `orgs/tbhb-dev/projectsV2/1`, the repository is `tbhb-dev/agent-orchestration-poc`, and the shared implementer account is `tbhb-agent`. A `user.login` read verifies the shared account only and cannot identify the intake agent.

No ordinary worker, reviewer, or coordinator writes a stub. The coordinator passes requests from a worker's final report or source PR or issue comment until messaging exists. An agy worker may request intake but agy does not run it. The intake agent reports the disposition to the coordinator, who relays it to the requester and records its link at the source. The coordinator records the stub's canonical Project URL, not a new issue number, for deferred work.

The requester supplies a proposed title, two or three sentences of what and why, the plan reference or origin, a source URL or `operator`, related issues and known blockers, and its harness and model. Intake asks for missing facts before a write. It may propose a conventional title and classification but does not invent an origin, source, or requester.

## Classification and duplicate search

Use the [stub template](stub-template.md) and the [workflow reference](../src/content/docs/guides/workflow-reference.md). Product capability changes are features and require an existing fitting epic. Restoring promised behavior is defect work. Keeping the repository, process, tooling, or documentation working is chore work. Use experiment for a bounded run that commits raw evidence, and spike for a question handled through reading or analysis. Incident applies to a declared event. Refuse a feature without a fitting epic and send the proposed epic decision to the coordinator.

Choose Type from the Project's current class values. Choose Priority as Standard for work in an initiative or an operator priority track. It also applies if written dependencies lead to an open initiative issue. Otherwise choose Intangible. Never assign Expedite. Work type is Planned when a planning act chose it before an event forced it. It is Unplanned when an event forced it before the next planning review. Incidents and SEV1 or SEV2 work are Unplanned. Set Severity only for a defect or incident. Estimate Size using the workflow reference's changed-line unit. Keep every assigned value in the draft body as well as the corresponding Project field when that field exists. A missing required Project field or option makes the draft Invalid and blocks conversion.

Before every create, search all open repository issues and every Project draft, paginating to completion. Search the proposed title and distinctive terms from the what and why, then inspect each plausible match's body, source, and relationships. Record the exact search terms and completed REST paths. A match with the same intended outcome is a duplicate. Return its canonical item or issue URL without another write. A partial or rate-limited search is incomplete and requires refusal. Use `GET repos/tbhb-dev/agent-orchestration-poc/issues?state=open&per_page=100&page=<n>` and `GET orgs/tbhb-dev/projectsV2/1/items?per_page=100&page=<n>`, filtering the latter to draft content. The issue list includes pull requests, so exclude entries with `pull_request` when comparing issues.

## Draft write and reply

Only after activation, use the [organization draft endpoint](https://docs.github.com/en/rest/projects/drafts?apiVersion=2026-03-10) to create the draft with the template body, then set Status Backlog and all available Project fields. Draft title and body edits use the documented [updateProjectV2DraftIssue mutation](https://docs.github.com/en/graphql/reference/projects#updateprojectv2draftissue) because the REST draft endpoint only creates items. Read the item and its fields back before reporting created. Never create a repository issue at this stage. Invoke #206's shared `mise run stub:validate -- <input-json>` with the current title, body, all fields, epic, plan or origin, and source metadata before each draft write. Re-read and check again after each edit. Record Valid or Invalid and the body digest plus failed rule names in Validation detail when those fields exist. Until #206 provides the task, or when a required field is absent, report Invalid and do not claim a ready stub.

Return exactly one disposition: `created`, `duplicate`, or `refused`. Include the canonical Project item URL or matching issue URL when one exists, assigned Title, Class, Epic, Type, Priority, Work type, Severity, Size, Validation, blockers, and the search terms. For refusal, include the missing fact or failed rule and route the decision to the coordinator. Do not silently drop a request. A refusal without an item uses `item URL: none`.

## Refinement and conversion

The coordinator selects a Valid Backlog stub at the refinement rhythm of [#163](https://github.com/tbhb-dev/agent-orchestration-poc/issues/163). The operator decides work requiring the operator. Record the decision-maker and UTC decision time before conversion. Drafts have no review comments. Review begins on the issue after conversion to Refinement.

Immediately before conversion, read the fresh draft body, title, and every Project field, then invoke the same #206 task. Refuse conversion unless the complete current input is Valid. Create an issue with the form headings `Goal`, `Context and links`, `Dependencies and paths`, `Allowed paths`, `Acceptance criteria`, `Evidence required`, `Docs impact`, and `Out of scope`. Write `unknown` in every section that the stub does not yet resolve. Copy the class, area, phase, and harness labels required by the workflow reference, plus all available Project values. Link the fitting epic as parent and add native blocked-by links. Add the issue to the organization Project with Status Refinement. Read back its body, `user.login`, labels, parent, blockers, Project item id, and all fields before deleting the draft. Stop on an incomplete or mismatched read.

The issue's first comment is the conversion record. Use these exact keys on separate lines: `Stub Project item id: <integer>`, `Stub URL: <URL>`, `Decision-maker: <coordinator or operator account>`, `Decision time UTC: <YYYY-MM-DDTHH:MM:SSZ>`, `Old Project item id: <integer>`, and `New Project item id: <integer>`. For Standard priority, report both ids to the coordinator and wait for the coordinator's rank replacement and read-back under #201 before deleting the draft. Delete only after the issue, conversion comment, copied values, and rank replacement are confirmed. Never claim draft conversion in place is verified.

The #90 reviewer records verdicts on the issue. A ready verdict is refused while any form section contains `unknown`. Existing Backlog issues from before activation remain issues and are inventoried separately from new draft violations. The coordinator later posts the activation record and sanitized live draft and conversion acceptance record to #198. The activation comment specifies the UTC time, policy version `1`, and `docs/briefs/intake-brief.md` at the merged commit.
