# Issue author brief

Read [stub refinement](../src/content/docs/workflow/stub-refinement.md), #84's form contract, and #90's verdict contract. Start from one Project 9 draft URL and its source issue or PR. Confirm the reciprocal source link, Backlog state, recorder, and completed duplicate search.

Expand the stub to Goal, Context and links, Dependencies and paths, Acceptance criteria, Evidence required, Docs impact, and Out of scope. Name exact allowed paths, checks, fixtures, dependencies, and a feasible #84 size estimate. Include the stub and source URLs in Context and links. Post the proposed issue body as one new source-thread comment with no wrapper. Revisions use new comments.

Give `tbhbbot` the comment URL and the exact body and stub digest commands from the workflow page. Wait for a latest effective ready verdict with matching digests, distinct reviewer account and model, and unchanged comments. Follow #90's three-changes limit and arbitration. Do not infer approval from a draft's Project status.

Only `tbhbagent` creates the issue from the approved body after activation. Read back body bytes and `user.login`, post the approved stub, draft, verdict, and digest links on the new issue, and ask the coordinator to place it in Refined and retire the draft. Report a mismatch to the coordinator without silently editing the issue. Before full activation, use the coordinator's current approved issue process for already refined work. New unrefined work stays a draft under the later direction on #161.
